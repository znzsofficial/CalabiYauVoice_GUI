# Android 架构审查修复（2026-11-17）

本轮覆盖子代理审查中的正确性问题及可直接落地的性能改进，保留现有导航/共享元素、账号隔离、原子资源下载与 Wiki 分层。已随 [2.2.1（62）](releases/2.2.1.md) 发布，产物与验证以该记录为准。

## 修复范围

### 请求取消与加载状态（D2、D4）

- `ReadSingleFlight` 将同 key 读请求协调从 OfflineCache 中抽出；旧 owner 取消时，仍 active 的 follower 最多接管一次。当前读者被取消必须退出，连续接管失败转为可重试错误，不无限重试或创建全局常驻 scope。
- `LoadState` 为上游取消/异常生成明确错误，仅当前请求版本可执行 finally 收尾；保留新网络成功（包括空结果）优先于磁盘预取的规则。预取之后刷新失败不再吞掉错误。
- `WikiEngine.safeGet` 改为 suspend，调用 shared `awaitGetString`；取消绑定持续到整个 body 读取及 Response 关闭。`fetchString` 同步采用此入口；读重试策略不变，不更改写请求。
- 角色详情纯解析不再请求图片：头像、技能图和故事封面移至 API 组装阶段。同步补图/壁纸函数迁移为 suspend；取消不转换为缺图/旧壁纸成功。

### Hub 与搜索快照（D3）

- 只有**在线、完整**成功列表可以形成跨 Hub 重建的快照。离线/部分结果仍在当次页面显示并保留 LoadState 元数据，下次进入重新验证；失败更新撤销其“免验证快照”资格，不清空当前可见数据。
- 快照发布检查清理代数和同类请求序号，清缓存/晚到旧请求不能回填；接入 MemoryCacheRegistry。
- 搜索不再维护独立永久列表缓存；优先读取当前完整 Hub 快照，否则重建时调用已有 API。观察快照变动和清理代数，不额外请求身份猜测数据。

### 工具输出与资源（D1、D5、R1）

- `ToolOutputTransaction` 先写同目录临时文件，完成后原子占用唯一新名称，使用 Android API21起可用的 `Os.rename` 发布。不会截断旧同名文件；失败清理临时文件及自己占用的目标，不删除旧文件。
- 九宫格、格式转换、裁切、放大、拼图和 GIF 帧输出使用实际发布路径；九宫格/拆帧失败清理本输入的已产出文件。
- GIF 合成先写临时文件，只有 finish 成功才发布；编码器提供 close/abort，finish flush 失败也关闭自有流，显式区分借用流。每帧、像素映射、量化训练和部分CPU图片循环有取消检查，离开子页按原 scope 取消，不引入后台服务。
- 工具 DSL 把当前 Job 通过线程上下文传给阻塞算法检查点，输入关键参数在启动时快照化。成功文件只在任务仍有效时反馈；已完整发布的文件不会因页面离开被任意扫除。
- 图片解码先读 bounds，用最大堆三分之一/最多128MiB和每像素32字节工作集估计限制过大输入/输出；拒绝时显示“图片尺寸过大，请缩小尺寸或减少输入图片”，不悄悄降低导出分辨率。该预算是保守工程界限，不是实测峰值保证。
- 拼图不再同时持有全部原图和缩放副本：先计算尺寸/输出预算，再逐张解码直接绘制到目标并回收。GIF帧、拼图目标及关键失败路径放 finally 清理。

### 性能及维护（R2–R5）

子代理复核进一步发现并修复：预览也要安装当前Job上下文，并对预算/解码失败显式显示错误（不能让异常逃逸或一直转圈）；放大和压缩预览的Bitmap在finally释放。GIF CENTER_CROP/FIT直接向目标大小画布绘制，避免极端宽高比先放大成巨型中间Bitmap。新增预览预算错误与取消传播测试。

- SearchViewModel 取消构造即联网，下载页首次进入调用 ensureLoaded；Hub 地图依赖按相关路由启用。
- 留言板身份轮询限于 STARTED；WebView 所有者将宿主 RESUMED 状态同步到主窗口及新旧弹窗，销毁逻辑不变。没有在单页调用全局 pauseTimers，不能据此宣称后台JS完全停止。
- 剧情目录从整组 lazy 改为标题与每两张卡片一行独立 lazy，链接也逐行；保持源顺序和页面链接。
- shared 无 Compose 源码使用，移除 Compose/UI/lifecycle 插件与依赖，显式声明 coroutines-core；Android/Desktop 编译验证其依赖完整性。serialization-json 仍为1.13.0。
- Wiki feature guide 移除裸 cachedPage 示例，改为 CachedWikiApi，避免复制“离线写永久内存”的旧模式。
- 新阅读页的二次解析仍保留：它承担缓存发布和读取两道校验，目前没有CPU实测证据支持进一步优化。没有为此引入全局DOM缓存，也没有进行机械模块拆分。
