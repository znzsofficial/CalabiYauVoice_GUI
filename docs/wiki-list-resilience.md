# 地图、武器、角色列表健壮性（2026-11-12）

纳入 [2.1.29（59）](releases/2.1.29.md)，最终发布状态以发布记录为准。

## 数据来源

- 地图卡片：`{{游戏地图|模式名}}` 的 parse HTML，模式目录仍由 `MapListApi.GAME_MODES` 定义。
- 角色卡片：`{{阵营角色|阵营名}}` 的 parse HTML，四阵营由 `CharacterListApi.FACTIONS` 定义。
- 武器：Semantic MediaWiki `action=ask` 查询四类武器及使用者、类型、介绍，再补图片。
- 战斗模式详情的地图名单：`模板:卡拉彼丘` 的 wikitext；它不是以上三个列表的统一数据源。

## 本轮修复

1. **卡片身份与图片分离**：共用 `WikiListCards` 只在已识别卡片容器中提取唯一站内正文链接；按链接目标而非 tooltip／显示别名确定名称。排除文件、特殊页、外站与多正文链接歧义。缺少图片仍保留条目，支持 lazy 图片与协议相对地址；同一名字重复出现时可用有图记录补齐无图记录。
2. **新旧地图结构同时读取**：`.klbq-map-card` 与 `.hvr-bounce-out` 一同解析，避免部分模板迁移时整页旧卡被跳过。角色沿用当前已验证 `.hvr-bounce-out`；未知新结构需要明确适配，不抓全页所有链接冒充名单。
3. **入缓存前验证**：地图／角色的 parse JSON 错误、无卡片或已识别卡片缺少唯一身份不能覆盖最后有效磁盘内容。磁盘预取同样验证。`模板:卡拉彼丘` 至少需解析出模式地图映射才接受网络响应。无法从 HTML 检测上游完整删除了一张卡的情况，不能把这些校验称为服务端总数证明。
4. **部分加载显式失败**：三种列表分组模型加入 `loadError`；失败分组仍保留固定位置，展示错误与重试，避免武器 Tab 缩位或把失败说成没有条目。首页地图预览也区分失败。缓存基类增加默认允许的 `shouldCache` 钩子，仅这三个 API 拒绝缓存含失败分组的汇总；成功分组仍由磁盘缓存保存。重试由用户触发，无循环自动重试。
5. **武器分页完整发布**：`WeaponListSource` 跟随 `query-continue-offset`，每类全部成功后合成并验证缓存。失败尾页、重复记录、不前进游标、超出 100 页、结构错误均拒绝发布残缺分类。旧首分页缓存含 continuation 时不视为完整。图片补充失败不再丢弃已解析武器分类；角色立绘补充失败亦保留名单。图片空映射不覆盖既有有效图缓存。
6. **导航模板解析**：按模板作用域配对 group/list，支持跨行、嵌套 Navbox、地图链接别名／锚点，忽略注释和 nowiki；按战斗模式链接目标确定模式名。重复冲突的模式定义不互相覆盖。未动态扩充模式、阵营或武器大类目录。
