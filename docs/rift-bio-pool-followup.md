# 维里昂裂隙与生化卡池补全

本专题初次实现纳入 **2.1.24（54）**。下文初始数据核对日期为 2026-11-02；初始发布状态和构建校验见 [2.1.24 发布记录](releases/2.1.24.md)。**2026-11-14 复验已确认“盗取”正式索引为221**，见末节，旧快照的缺索引结论不是当前状态。

## 维里昂裂隙

- 实际页面：`维里昂裂隙`，模板 `{{地图}}` 提供简介、支持模式“弦溯战线”和平台“PC端”；有地形图，无地图概览图集或更新历史。本轮不虚构后两者。
- `{{游戏地图|弦溯战线}}` 已返回标准 `klbq-map-card`，因此地图列表增加相应模式，主页地图预览也使用同一数据。搜索补充维里昂裂隙兜底标题。
- 战斗模式中的地图按钮现可打开原生地图详情；图鉴入口仍只在“外观与图鉴”，没有放回战斗模式。
- 详情头图优先列表传入图，其次从本页 `{{背景}}` 渲染的 body background 规则读取概览图；再回退地形图，不新增 imageinfo 请求。
- 没有图片且请求已结束时显示“暂无地图图片”，不让骨架无限闪动。
- 地图模板名称精确匹配，避免 `地图导航`、`地图音乐` 被错当 `地图`。
- 地图详情采用现有版本化 keyed cache，防止清缓存后的旧写入复活；离线回退不成为永久内存成功。

## “盗取”遗漏的实际原因

本轮依次核对了 Wiki 的完整 PC 图鉴、分享卡表和 Lua 数据源：

- `模块:生化卡牌/Data` 有 **盗取，cardid=20351047，quality=3，teamType=晶源体，maxLevel=1**。
- PC 图鉴中也有这张卡，且文件 alt 直接携带 `20351047`。
- `MediaWiki:ZombieCardList.json` 当时只有超弦体 116 张、晶源体 95 张，**没有 20351047，也没有对应的 index**。Lua 键 `80219` 是源数据键，不是分享码位图索引。

所以这是两份 Wiki 卡表更新不同步，不是同名卡串图或阵营筛选问题。不能从 cardid、Lua 键、排序位置或最后一个已知 index 猜新的编码位。

## 补全策略与明确限制

- PC 解析结果新增独立 cardId，在缩略图转换成不透明原图 URL 之前从 alt/文件名提取。图片索引也优先使用明确的 cardId。
- 生化卡组页复用**已经加载的 PC 图鉴**，补全分享卡表里遗漏的非天赋卡；只接受明确 ID、阵营和 2–4 品质，不合成未知 ID，不跨阵营认领已有 ID。
- 补全卡使用 `index=-1` 标记索引未知。不会占用 212 等推测 bit，也不会将部分已知卡生成的码当成完整卡组码。
- 卡池可以选择“盗取”；未索引卡会显示“可加入卡组，暂不能生成分享码”。发布区列出这些卡名。
- 默认禁止发布这种选择。用户**明确勾选“仅发布完整卡牌列表，不生成分享码”**后，才能发布完整卡牌列表；发布 wikitext 的分享码参数留空，不生成 Widget，也不写分享码调试字段。未曾在真实 Wiki 上执行发布来测试。
- 用户未勾选时，API 的 `allowMissingShareCode` 也默认 false，绕过 UI 不会意外生成缺卡的码。
- 已有完整索引的卡组照常按原规则编码。Wiki 日后补上某张卡的 index，合并时直接优先其正式记录，不覆盖或保留手写假索引。
- 全量快照验证发现不止“盗取”：补全后卡池为超弦体 123 张、晶源体 99 张。新增的未索引卡遵守同一显式“无分享码列表”规则；这个数量是当日源数据结果，不是应用硬编码。

**当时尚未解决的外部条件**：截至11月2日快照，“盗取”尚无正式分享码索引。后续已由上游补齐（见末节），代码补全本身从未冒充协议数据已齐全。

## 2.1.25：Android 地图正则修复（2026-11-03）

- 用户报告莱布伦城和搜打撤地图打开时报 `Syntax error in regexp pattern near index 49`。根因是 `MapDetailParsers` 读取 `{{背景}}` 时使用的 CSS body 正则以未转义的 `}` 结尾。
- Android 的 ICU 正则引擎拒绝这个写法，桌面 JVM 却接受，因此 2.1.24 的 JVM 单测和真实页面快照回归未暴露该问题。影响范围是进入背景样式解析分支的地图，并非地图数据失效或网络错误。
- 修复只将末尾字面量右花括号改为 `\}`，保留背景图域名检查、地形图、简介和缓存行为；纳入 2.1.25，不覆盖已发布的 2.1.24 APK。
- 新增合成回归覆盖两张报告地图的背景模板、`background` / `background-image`、无关样式隔离、缺失／残缺 CSS 下保留详情；已有裂隙真实 fixture 和完整本地快照继续执行。莱布伦城没有新增联网抓取，不把合成输入称为真实页面验证。
- 另外用 Windows 本机原生 ICU `uregex_open` 核对：原发布正则返回 `U_REGEX_RULE_SYNTAX`、offset 49；修复后的 body 正则及 URL 正则均返回 `U_ZERO_ERROR`。这是原生 ICU 语法检查，不是 Android 设备运行；纯 JVM 测试无法保证 ICU 兼容性。
- 地图专项 15 项全部通过；地图修复阶段 Android 全量 361 项、9 项可选跳过、无失败，三组外部完整快照实际执行。用户在发布前反馈其它内容已测试无问题；代理没有连接设备，未冒称自行真机验收。最终回归与产物见 [2.1.25 发布记录](releases/2.1.25.md)。
