# 资源下载：任务、选择与文件完整性

## 入口与状态

- Android `feature/download/DownloaderScreen.kt` 组合搜索、分类、文件选择与立绘状态；
  `SearchViewModel` 管理搜索，`CategoryFileSelectionState` 单独管理一个弹窗请求。
- 文件弹窗每次打开、关闭、切换模式/分类都会取消旧 Job 并更新代数。即使底层迟到响应不可取消，
  也不能覆盖新弹窗。失败与空结果分开；加载中/失败时禁止确认，避免误写空的手动选择。
- 共享 `WikiEngineCore.groupCategories` 将同一官方角色的搜索家族合并，保留全部分类种子；
  分类树从 root + 全部家族种子展开，而不假定名字前缀相似的分类一定存在父子链接。
  跨种子全局去重，循环安全，同层请求并发限制为 4。列表 key 不再依赖非唯一显示名。
  此共享语义同时接入 Android 与 Desktop；下面的任务落盘恢复、媒体扫描和恢复提示为 Android 实现，
  不应误读为 Desktop 已新增同样的持久任务机制。
- Android 文件搜索统一委托共享双路径实现；HTTP、HTML 拦截、无效 JSON 和 MediaWiki `error`
  均应报错，不得静默返回前缀搜索的部分结果或“无文件”。空分类的 `batchcomplete` 响应仍是合法结果。

## 下载请求与恢复

- `ResourceDownloadRequest` 是任务的深拷贝快照，包含原文件/分类/手动选择、保存目录、并发数和 ID。
  错误事件携带该请求。Snackbar“重试”不能从当前 UI 重新构造另一份下载任务。
- 开始前尝试用 SharedPreferences `commit` 写入 `pendingResourceDownload`，成功结束时再清除。
  写入或清除失败只提示不能跨重启恢复，不拒绝本次下载，也不把已完成文件报成失败。
  下载失败的 Snackbar 会替换当前提示，因此失败文案必须带上尚未确认的恢复警告，不能只留在已被关掉的提示里。
  取消、下载失败、进程中断仍保留恢复槽。重新进入资源下载页可“继续原任务”或“放弃任务（保留文件）”。
- 系统网络状态只驱动页面提示。未通过 `VALIDATED` 不能预先拒绝下载；能否下载由实际请求决定。
- 分类下载先取完各分类。查询失败不是空结果：已取到的分类继续下载，失败分类在结束后汇总；全部失败时不能显示成“没有可下载的文件”。
- 当前只保留一个恢复槽：主动开始另一任务会用新的明确选择替换恢复槽；错误事件仍绑定自己的原请求。
- “取消下载”取消任务 Job，底层 OkHttp 调用绑定协程取消；未完成临时文件按既有逻辑清理。
  已完成文件保留，重试核验通过后跳过，不会重复生成 `(2)` 副本。
- **这仍不是 WorkManager/前台服务。** 切到后台不保证系统持续运行下载；系统杀进程或重启后
  不会自动下载，用户回到页面后明确继续。此恢复不要求、也不声称可靠的后台执行或字节级断点续传。

## 清单与完整性

- Android 的记录保存在应用内部 `filesDir/download_manifests/<保存目录 canonicalPath 的 SHA-256>.tsv`，
  不再在公共下载目录创建/替换 `.calabiyau-downloads.tsv` 或其 `.tmp`。清单是内部账本，不应因公共目录不支持隐藏文件重命名而阻断下载。
  Desktop 仍使用下载目录下的 `.calabiyau-downloads.tsv`。字段均为 `文件名\tURL\t字节数\tSHA-256`。
  在目录互斥锁内安排名称。名称分配有变化时发布一次；本批新确认的长度/哈希在结束时再发布一次。
  已校验通过的文件不触发重写。进度回调仍串行递增。调度层不得在调用原子下载前删除目标，失败时保留原文件。
  取消后的清单发布必须先等子任务结束，再在锁内复制记录；不能在已取消的 `joinAll` 返回后直接遍历仍可能被改写的清单。
- 只有长度和 SHA-256 均相符的非空文件才跳过。非零、等长损坏文件也会重新下载。
  下载函数若没有实际产出非空文件，不能记成功。
- 兼容旧的两列清单，但旧文件没有可验证指纹，首次继续时保留原文件名、重新下载一次建立指纹。
  不会覆盖没有清单归属的同名用户文件；文件名冲突仍确定性加后缀。
- Android 私有记录尚不存在时，尝试只读导入原目录中的旧清单；不存在、被目录占用或无法读取时跳过。
  不删除、不改写旧清单，私有记录建立后以其为准。卸载/清应用数据会丢掉私有记录，不能再凭非零文件大小宣称已下载完整；
  若也没有可读旧清单，同名现有资源作为未归属文件保留，新任务可能生成带后缀的副本。
- 这些哈希用于校验“与本地已确认下载版本一致”，不是上游签名验证；不能凭本地 SHA-256 保证
  来源真实性，也不会检查同 URL 的远端内容是否更新。目录被外部程序主动改动时可能需要重新下载。
- 单项失败不使已成功项丢失校验记录；下次只补失败/损坏项。取消时未确认输出不获得完成指纹。

## UI 与媒体扫描

- 日志允许重复文案，不以文案作为 LazyColumn 唯一 key；并发追加使用原子更新，最多保留 1000 行。
  资源下载页已移除运行日志入口，不再订阅整个日志列表触发重组；进度、失败重试和下载历史仍保留。
- 媒体扫描只处理本批结果列表，在 IO dispatcher 分批通知系统，不再在主线程遍历整个历史目录。
- 前台恢复提示和取消按钮使用现有页面样式；没有为了修复引入另一套下载队列 UI。

## 回归测试

- `CategoryFileSelectionStateTest`：A→B 迟到响应、关闭/模式变化、错误不可确认、重试和空手动选择。
- `ResourceDownloadRequestTest`：深拷贝、序列化重建、原保存目录与并发数、错误事件绑定原任务。
- `DownloadManifestStorageTest`：Android 私有路径、目录隔离与 canonical 路径一致性。
- `WikiEngineCoreQueryTest`：错误 JSON、合法空分类、家族合并、独立种子、循环去重、搜索部分失败。
- `DownloadPoliciesTest`：恢复记录失败不阻断、下载失败保留恢复槽、分类失败不丢已取到的文件、取消不伪装成分类失败。
- `WikiEngineCoreDownloadTest`：名称碰撞、目录互斥、清单兼容、同长度损坏、部分失败重试、取消释放锁、失败不预删原文件、已校验重试不重写清单。
  新增整链用例覆盖调度层→共享原子下载适配器→真实文件替换，避免平台层按非零长度跳过损坏文件。
  Android/Desktop 都使用此适配器，不能在平台包装层重新增加 exists/length 短路。
  私有记录用例覆盖公共目录清单被同名目录占用、旧清单只读迁移、用户同名文件保留及重试/损坏文件修复。

运行 `:androidApp:testDebugUnitTest :shared:jvmTest :desktopApp:test`，不用线上 Wiki 请求。
真机的后台限制、通知权限和系统媒体库显示效果仍需设备回归。

### 设备回归清单

1. 慢网络下打开 A 分类文件选择、关闭、打开 B；确认标题、文件和手动选择始终属于 B。
2. 让文件列表加载失败，确认显示错误且不可提交空选择；重试成功后恢复正常确认。
3. 开始下载后取消，已完成文件保留；继续原任务，确认目录/选项不受当前页面选择或设置变化影响。
4. 下载过程中终止进程，再启动 App 打开资源下载页；确认出现恢复提示，必须明确点击才继续。
5. 修改一个已下载文件（含同长度损坏），确认继续任务会修复它而跳过未损坏文件；
   使用旧两列清单时确认一次性重下不改原文件名，也不覆盖未归属的同名文件。
6. 大量旧图片目录下，单次下载的媒体扫描不应卡住 UI。运行日志入口已移除。
