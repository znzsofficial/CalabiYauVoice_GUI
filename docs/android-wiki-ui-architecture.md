# Android Wiki 页面与复用组件

2026-11-04 页面重构，纳入 **2.1.26（56）**。最终提交、发布状态与指纹以 [2.1.26 发布记录](releases/2.1.26.md) 为准，下方验证过程保留阶段性事实。

## 范围

落实架构审查中的公共详情、选择器、图片保存、分区状态、推进卡牌网格，以及生化、平衡、投票的业务编排整理。没有新增依赖、统一各模式品质枚举、重写分享码协议，或创建一个用大量开关控制的万能图鉴页面。

此前审查列作“后续”的首页／搜索／WebView 大规模拆分不属于本次核心重构；不因文件较大就改动已验证的导航、Cookie 票据、文件选择回调、弹窗生命周期与共享元素逻辑。

## 共用 UI

`core/ui/WikiSheetComponents.kt`：

- `WikiSheetFrame`：统一 Material 弹层样式和展开状态，不携带业务规则。
- `WikiScrollableSheet`：短详情的整体滚动容器，图片头部与正文一起滚动。`CatalogDetailSheet` 及生化、推进卡牌详情使用；避免只允许固定高度正文滚动而头部占满短屏。
- `WikiContentSheet`：有界 LazyColumn，供长内容使用。掉落池保持逐物品 Lazy item，不回退成一个巨大的拼接 Text。
- `WikiSelectionSheet`：搜索／附加控件插槽／有界选项列表。道具分类、画廊分区、角色选择和武器大类开始复用；选中后关闭、分组与过滤仍由各自调用者决定。武器二级选择复用基础弹层，不将其分类语义抽进公共组件。
- `SelectionOptionRow`：共用选中态、触控区域、标题、可选前导内容；用于道具和卡组选卡。
- `DetailField`：多行纵排详情字段，生化与掉落详情使用；`DetailInfoRow` 可选择 stacked，横排行为保持兼容。
- `CatalogEmptyResults`：列表内无匹配结果，可带清除搜索／筛选按钮；不代替全屏网络错误或初次加载状态。

`CatalogDetailSheet` 不再自行实现另一套弹层外壳；无图片／自定义图片内容时不留空图片头，图片切换条可横向滚动。各页面继续传自己的品质名、色彩和正文，不根据数值假定各游戏模式品质相同。

## 图鉴键与分区状态

`CatalogKeys.kt` 对源集合在过滤／排序**之前**分配字符串身份与重复出现号。不用 data class hashCode 或过滤后的索引作为条目身份；重复身份用出现号区分，字符串长度前缀避免分隔符造成键碰撞。

- 道具、推进卡牌、生化 PC／移动端／卡组列表使用源集合键；完全相同的源副本不重复展示，同名但内容不同的变体仍保留。
- `SectionSelectionState` 按分区键保存选择。空预取／刷新不清空选择，分区换序后仍选原项；仅当非空新结果已不包含原项时退到首项。
- 画廊和玩家装饰不再每次 `state.data` 变化就强行回到第一个分区；页面间选择按 pageName 隔离，重复分区名按出现号区分。
- 这两页的网络验证明确 `allowMemoryCache=false`，避免离线预取／已有内存使后台验证变成没有联网的内存命中。

## 图片保存

`ImageSaveComponents.kt` 统一画廊和装饰的保存确认、文件名生成、目录配置、系统下载提交与错误反馈。通用 `ImagePreviewDialog` 默认保存路径也使用同一协调函数。

- 复用现有 `enqueueDownload`／系统 DownloadManager，不引入第二套下载实现。
- 只支持该下载器接受的 HTTP(S) 图片 URL；Bitmap、内容 URI 的专用保存不强行复用。
- 入队后提示 **“已开始保存”**，不再在任务尚未完成时说“已保存”；完成通知仍由系统 DownloadManager 管理。
- 不修改资源下载原子写入、manifest、版本安装包清理或 WebView 的认证下载链路。

## 超弦推进卡牌

`StringerPushCardScreen` 使用 `LazyVerticalGrid(Adaptive(168.dp))`，简介、搜索、筛选和空结果作为跨列项，卡牌逐项懒加载；不再 `LazyColumn → 单个 item → FlowRow → 全部卡牌`。分类、角色、品质、排序与搜索仍在本地计算，筛选状态通过 rememberSaveable 保留。卡牌详情使用公共整体滚动弹层。

## 生化卡牌与卡组

### 按页签依赖加载

`BioCatalogTab`、`BioTabLoader` 和每页签独立 `CachedWikiApi` 替代聚合整页请求：

- PC：PC 卡牌页和可降级为空的刷新概率说明；不请求移动端／分享页／分享索引。
- 移动端：仅移动端卡牌页。
- 卡组：分享页、官方索引和验证过的 PC 卡表（复用 PC 缓存），不请求移动端。PC 表补齐缺索引卡池的约束不变。
- 分享页能解析时，编辑器依赖失败不拖垮卡组浏览；错误单独提供给编辑器并禁止发布。该降级结果不造成永久内存命中，再进入可重新尝试，显式刷新也会重试依赖。
- 取消仍抛出；未解析到 PC／移动端／分享页内容不会变成成功空结果。结果标明 loadedTab，页签的请求状态按 key 隔离，避免上一页签数据被当成本页成功。

### 编辑与提交

- `BioDeckEditorState` 管理可保存草稿、阵营切换、默认卡合并、选择上限、稀有度校验、导入与完整 payload 生成。测试不需要运行 Compose UI 或真实网络。
- 恢复后卡表暂时为空不会清空草稿；同阵营卡表重新到达不清掉选择，明确换阵营才清选卡。旧实现无条件在 `LaunchedEffect(selectedFaction)` 清除恢复的选卡已移除。
- 导入先成功解码再替换选择，失败不毁掉原草稿。失效卡 ID、品质不足、未登录、无名称等发布前拒绝。
- 缺失正式分享索引仍保留 `-1`；必须明确同意 `allowMissingShareCode`，才发布**全部已选卡**而不生成分享码／Widget。没有修改编解码器、猜索引或拼部分码。
- `BioDeckSubmissionState` 是显式单次写入协调器：重复点击单飞，成功／错误／取消均释放 busy；不自动重试 MediaWiki edit。
- 提交前后使卡组列表内存缓存及待发布旧读失效，包括取消／结果不确定的路径；切换页签后写入返回，也不能留下永久的旧分享列表内存命中。
- `BioDeckCardSelectorSheet` 独立承载选卡 UI，复用公共选择弹层与选项行，保留 artwork 身份查找、默认卡限制和缺码提示。
- PC／移动端完全重复的筛选条收敛到 `BioCardFilters.kt`，仍保存各自的筛选值；不把生化品质映射用于其它模式。

发布复审进一步修复：页签从成功内容移到常驻容器，加载／错误期间也能切换；编辑草稿提升到屏幕（不再归属 DECK 条件 lazy item）；发布完成用最新回调且只刷新当前 DECK；编辑表单仅标题点击折叠。公共长描述先限制滚动容器高度，再测量内部文本，避免同向嵌套滚动的无限高度错误。分区状态改用直接 Saver，不再通过 SideEffect 中转保存。详见发布记录的复审清单。

## 平衡与投票

`BalanceScreenState` 管理设置与数据请求、busy、错误和结果，不混入控件构建。每类请求有版本票据并检查取消，旧响应不能覆盖新响应；空查询使旧请求失效。原有 `BalanceFilterState`、Saved values 编码、草稿／应用／取消规则不变；草稿、排序和攻防切换不触发 POST。

`VotingScreenState` 管理配置、登录读取、选中项、显式提交及提交后的状态同步：

- 游客只读配置；提交期间阻止第二次提交和刷新覆盖写入状态。
- 投票写入只调用一次，不自动重试。部分失败也读服务器状态，以服务器结果纠正选择。
- 写入成功但刷新失败，保留已提交选择对应的乐观状态并准确提示，不谎称写入失败后自动补发。
- 取消继续传播，finally 释放 busy。纯选择比较／票数映射在 `VoteSelection.kt`，不再藏在屏幕文件中供状态层反向依赖。

这些是各页面独立的轻量状态持有器，不新增全局服务、DI 容器或统一“带重试的 mutation 状态机”。筛选本地状态依旧按具体业务保存。
