# 玩法系统原生页与完整导航分流

2026-11-17 实现，已随 [2.2.1（62）](releases/2.2.1.md) 发布，产物与验证以该记录为准。

## 页面范围

在原“玩法与养成 → 玩法系统”位置接入三个原生页，新增 Hub 搜索及保存路由 `mechanics|STRINGIFY / ROLES / AUGMENTATION`：

- **弦化**：开头简介、减伤公式及注释、纸片人/爬墙/飘飞说明、官方教学视频与更新历史。读取现网 Biliplayer 输出中的固定 `bvid` 与 `p` 参数，PC/mobile 重复播放器合并；不执行脚本。视频通过系统浏览器打开对应分P。
- **超弦体定位**：六种职责及24名角色，显示源缩略图和名字，点击进入原生角色详情。身份取 Wiki 链接全名，展示名可用原文简称（如奥黛丽→奥黛丽·格罗夫），不按名称前缀猜角色。缺图仍保留条目，名单缺项或定位冲突拒绝缓存。
- **弦能增幅网络**：系统简介、升级规则、4种模式共41行能量表、补充判定、历史更新和配图。保留一般爆破/排位以及各模式的字段、计量单位、现行规则与历史数据边界。

每页 `model / parser / source / api / Screen` 分层，放在 `feature/wiki/mechanics/`。章节横向选择，段落/资料行逐项 lazy，章节独立滚动保存；切换 MechanicsKind 使用独立组合域，加载、缓存和选择不会串页。保留原文入口、刷新、失败时旧资料和共享离线提示。

图片在正文展示源预览，打开原 Wiki 文件页查看；未把 `/thumb/` 当原图或提供错误的原图保存。移除正文外的导航箱、目录、样式、编辑按钮、`.leftPic` 看板娘和 `.resourceLoader`，不把站点挂件当历史配图。

## 共用与缓存

文案复查：来源行只标示 Wiki；视频/图片操作明确“在哔哩哔哩观看”“在 Wiki 查看图片”，不把分P标识或源文件名堆在按钮里，无障碍标签仍保留目标身份。内容解析失败显示简短状态，具体结构诊断写入 WikiParseLogger；Wiki 原文、公式、单位及历史标签保持原样。

- 从新人指南抽出小型 `core/wiki/reading/WikiRichText.kt` 和 `core/ui/WikiRichText.kt`，双方复用强调、可复制文字、SMW注释及链接处理。页面结构和完整性校验仍各自负责，没有新增通用网页渲染框架。
- 独立键 `mechanics_<kind>_v1`，复用 GAME_TIPS 存储类型；KeyedCachedWikiApi 隔离各页面，网络验证绕过内存预取，离线不成为永久内存命中。
- 检查 JSON 标题、对应页面章节/内容基线以及表格字段后才写磁盘；读取缓存后同样校验。拒绝半页、缺少视频、角色身份缺失/冲突、未知表头/缺字段/非法合并表格。新增合法条目允许，真实删除或结构改版需审核基线。
- 失败新响应不覆盖好磁盘；离线回退保留年龄，坏有效HTTP响应无回退时为 PARSE，完全无来源时为 NETWORK；取消透传。

## 完整导航的原生分流

`WikiNativeLinks.kt` 仅在 Hub 的 `WikiRoute.Navigation` 回调中启用：已映射目录页转原生，角色/地图/武器按已有成功列表快照的**精确文章名**匹配，未加载或未知则仍开原 URL，不增加网络请求。地图复用既有图像解析/导航入口；回调带当前页/遮罩检查。

仅接受本站 `/klbq/<标题>` 或单一 `index.php?title=` 链接；带非空锚点、历史版本/编辑/额外查询参数、未知子页、其它站点继续网页，避免改变目标含义。不把“好友”全页映射为仅互动道具子集，也不把超弦推进介绍页映射为卡牌子集。各页明确的“查看 Wiki 原文”仍原样打开网页。
